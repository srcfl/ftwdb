# Bootstrap benchmark: macOS ARM64, 2026-07-21

This is a developer bootstrap measurement, not a decision-grade comparison.
Criterion ran in `--quick` mode on an Apple ARM64 host with 16 GiB RAM, APFS,
Rust 1.97.1, and no controlled cache drop. The purpose was to validate the
harness and expose the first bottlenecks.

## Append 1,000 points as one transaction

| Engine/mode | Median-ish estimate | Throughput estimate |
|---|---:|---:|
| WattDB manual sync | 0.555 ms | 1.80 M points/s |
| SQLite WAL, `synchronous=OFF` | 0.647 ms | 1.55 M points/s |
| WattDB sync each batch | 5.61 ms | 178 k points/s |
| SQLite WAL, `synchronous=FULL` | 0.824 ms | 1.21 M points/s |

The setup phase creates the database and schema outside the timed section. Both
engines write one 1,000-row batch/transaction. This does **not** yet prove equal
physical durability on this hardware; the power-cut suite must validate the
acknowledged durable watermark for each configuration.

The result immediately identifies WattDB's per-batch sync path as a bottleneck.
Likely work items are group commit, fewer encoded bytes, vectored writes, and
measuring which sync primitive/filesystem barriers are actually issued. The
unsafe/manual mode is not a substitute for durability.

## WattDB query primitives over 100,000 one-second points

| Operation | Estimate |
|---|---:|
| Latest-revision raw range | 7.90 ms |
| Build 5-minute rollups from raw points | 9.59 ms |
| Read the already materialized 5-minute full range (334 buckets) | 2.67 µs |

The ~3,000x gap between rebuilding and reading materialized buckets is why the
automatic rollup pyramid is a core storage feature. The materialized state in
this milestone is in memory; persistent segment read costs, checksum work, and
cache state still need measurement.

## Reproduce

```sh
cargo bench --bench compare_sqlite -- --quick
cargo bench --bench storage -- --quick
```

Raw Criterion artifacts are generated under `target/criterion/` and are not
committed. Future benchmark releases will retain machine-readable result JSON,
container digests, input checksums, and physical write counters.
